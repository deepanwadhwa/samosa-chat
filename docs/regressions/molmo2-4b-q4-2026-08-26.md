## Defects found by real weights

- Initial real inference found an invalid visual-feature insertion using MLX
  `scatter`. It was replaced with shape-correct `scatter_add_axis` insertion in
  `src/molmo2/molmo2_model.cpp`.
- Initial live gateway inference evaluated memory immediately after `waitpid`
  and rejected the request while macOS was still asynchronously reclaiming
  Metal/wired pages. `src/samosa_gateway.c` now waits for at most three seconds,
  sampling every 100 ms, while retaining the same memory requirement and
  failing immediately on critical memory or thermal pressure.
- The runtime-only installer regression exposed temporary macOS launchd
  KeepAlive smoke gateways surviving their deleted staging homes. The installer
  smoke now disables launchd, uses the authenticated staged launcher to stop the
  real detached PID, removes its smoke home before publication, and has a
  regression assertion. All six stale test services were unloaded and the
  repeated release test left none behind.
- The first browser-grounding implementation prepended a second system message
  ahead of the UI's existing system context. Ornith's Jinja template correctly
  rejected that ordering with `System message must be at the beginning`. The
  gateway now merges all system context and its evidence contract into exactly
  one leading system message. The gateway regression sends the real UI shape
  and fails if a second system role reaches the backend.
- A generic `what is this?` turn was incorrectly escalated to fine detail by
  the text-only planner. The fine prompt began with chart-specific examples,
  causing Molmo to hallucinate a ResNet evaluation chart despite receiving the
  correct attachment path and pixels. Detail level is now selected only by
  explicit deterministic task wording, and image prompts require
  description-before-classification without assuming an image category.
- Comparison with the pinned upstream `processor_config.json` found that the
  global low-resolution crop must omit column tokens
  (`use_single_crop_col_tokens=false`) while the high-resolution grid retains
  them (`image_use_col_tokens=true`). The native processor and its unit test now
  enforce that exact split.

## Direct first-visual acceptance with Bonsai (2026-08-27)

The installed release `dev-48fdd7e82de6` was tested with Bonsai selected and
the user's exact `qwen3.6_35b_a3b_score.png` attachment
(`6ce6dc8da1e8de2c25c4b8209588395dbe3046566b8540263b07095b9d1e8af9`).
The request was the first turn of a Bonsai-bound conversation and asked Molmo
to count the charts and point to every center.

- HTTP 200 completed in 24.990457 seconds.
- The response model/provider were `molmo2-4b-mlx-q4-v1` / `molmo2_4b`.
- Molmo returned one `coords` group containing exactly twelve grounding points.
- The only model process sampled during inference was `samosa-molmo2`, with a
  3,949 MB `footprint` reading; Bonsai was not co-resident.
- After the response, no Molmo process remained and Bonsai was ready again.
- A text-only continuation in the same conversation returned
  `BONSAI RESTORED` from model `bonsai-27b-1bit` in 1.955872 seconds, proving
  that the conversation binding remained on Bonsai after the visual turn.
- System `Swapins` and `Swapouts` remained zero, with no thermal or performance
  warning recorded.

This run also exposed an inherited-client-socket defect in asynchronous backend
restore: the restarted text child could keep an already completed SSE response
open. Accepted gateway sockets are now `FD_CLOEXEC`, and the regression applies
a bounded client deadline so this lifecycle failure cannot silently return.

## Installation and remaining public-release boundary

The verified package was copied atomically to
`~/.samosa/models/molmo2-4b-mlx-q4-v1`; byte-for-byte directory comparison
passed. The installed gateway reports `molmo2_model_ready: true`, and the
Settings model card reports the native package as Ready.

No external artifact was uploaded. A public one-click UI download still
requires an explicitly authorized release location and immutable per-artifact
URLs/hashes in `assets/models.json`. The catalog therefore honestly retains
`provisioning: native_pack` instead of pretending a public download exists.
Broader BF16-versus-Q4 task-quality parity and hostile/dynamic video corpora
also remain public-release gates; they do not invalidate the completed local
conversion and machine-safety qualification recorded here.

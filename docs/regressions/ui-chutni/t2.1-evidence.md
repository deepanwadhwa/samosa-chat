## What was built (`src/samosa_gateway.c`)

- `GET /v1/models/catalog`: loads `assets/models.json` fresh per request
  (matching `serve_root_html()`'s existing no-cache-on-disk pattern),
  validates it (`catalog_validate()`), and layers live facts on top
  (`emit_catalog_entry()`). Covered by the fail-closed dispatcher gate from
  the prior commit automatically — it is not on the legacy exemption list,
  so it required no new auth wiring, which is itself a small proof that
  fix works as intended for new routes.
- **Validation before trust** (`catalog_validate()`): rejects duplicate
  model IDs, duplicate artifact `install_path`s (across every model, not
  just within one), malformed SHA-256 (not exactly 64 lowercase hex),
  malformed/negative byte counts, unsafe relative `install_path` (absolute,
  or containing a `.`/`..` segment), unknown `backend_kind`, a
  `required_runtime_abi` that doesn't match the catalog's own
  `runtime_abi`, and artifact URLs on a host other than
  `https://huggingface.co/`. A validation failure returns `500
  catalog_invalid` and serves nothing — matches the acceptance item
  verbatim. All eight rejection cases have a dedicated regression test.
- **Compatibility** (`catalog_platform_matches()`): compares the compiled
  OS/arch (`__APPLE__`/`__linux__`, `__aarch64__`/`__x86_64__`) against each
  entry's `supported_platforms`. Deterministic and directly testable (a
  fixture entry declaring `windows`/`x86_64` reliably comes back
  `compatible:false` with a non-null `compatibility_reason` on this
  machine).
- **Install-state detection** (`resolve_installed_artifact()`,
  `artifact_is_present()`): resolves each named artifact via the *existing*
  per-backend fields (`g->qwen_model`, `g->tokenizer`, `g->bonsai_model`,
  `g->bonsai_mmproj`, `g->ornith_model`) rather than re-deriving paths from
  `install_path` generically — Qwen's real layout (a release-staged model
  directory) differs from Bonsai/Ornith's flat `models/` convention, and
  only these existing fields are correct for both today. An artifact counts
  as present only if the resolved file exists **and** its size exactly
  matches the catalog's declared `bytes`; a truncated/wrong-size file is
  never shown as installed. Verified end-to-end against the real machine:
  the real 24 GB Qwen model (all six artifacts) and the real installed
  Ornith model both correctly report `install_state:"ready"` with
  `installed_bytes` exactly equal to `download_bytes`, computed from cheap
  `stat()` calls only (measured: `time curl .../v1/models/catalog` = 8 ms
  with the real Qwen paths wired in — no hashing happens on this route).
- **Shared runtime dependencies** (`runtime_dependency_is_present()`):
  Bonsai and Ornith both declare the shared `llama-server` package as a
  `runtime_dependencies` entry; `install_state` requires it present
  (`regular_file(g->llama_server, 1)`) in addition to each model's own
  artifacts. A fixture proves a model with its own weights file present but
  the shared dependency absent still reports `not_installed`, not a false
  `ready` — matches the acceptance item ("shared runtime dependencies...
  reused without making an incomplete model appear ready").
- **Live capability degradation** (`emit_live_capabilities()`): a model's
  `capabilities` in the response is not the catalog's static declaration
  verbatim. An optional `role:"vision_projector"` artifact that isn't
  present drops `"image"` from the live list while `"text"` remains; Qwen
  (vision built into the engine, no separate artifact) is never degraded.
  Verified against the real catalog with nothing installed: Bonsai comes
  back `["text"]` only, Qwen stays `["text","image"]`.
- A stack-overflow was found and fixed during this work, not shipped:
  `catalog_validate()`'s original duplicate-path tracking used
  `char seen_paths[512][PATH_MAX]` (~2 MB of connection-thread stack).
  ASan caught it immediately (`AddressSanitizer: stack-overflow ...
  catalog_validate`) the first time the real endpoint was exercised
  end-to-end; cut to `[64][256]`, matching the catalog's actual scale (9
  artifacts today), with an explicit length check on `install_path` before
  copying so a future long path is rejected as unsafe rather than silently
  truncated.

## Remaining (do not mark T2.1 DONE)

- **Frontend still hardcoded.** `assets/app.html`'s backend `<select>`
  (`bonsai`/`ornith`/`qwen` options, hardcoded JS objects) has not been
  touched. The acceptance item "the frontend contains no authoritative
  hardcoded model availability" is unmet. Per project memory,
  `assets/app.html` hasn't had its T3.1 design-system pass yet either, so
  wiring the catalog into new markup ahead of that redesign risks visual
  inconsistency — worth confirming sequencing (this vs. T2.4/T3.1) before
  starting rather than assuming.
- **Corrupt-but-right-size artifacts are not caught.** `artifact_is_present`
  checks byte size only, not content hash — a bit-flipped file of the exact
  right size would incorrectly read as installed. This matches the spec's
  own two-tier design (fast identity/size/mtime by default; full "Deep
  verify" as a separate, explicit, on-demand action) but that background
  full-hash validation pass doesn't exist yet. Scoped out of this task
  deliberately, not forgotten.
- **`minimum_ram_bytes` is `0` for all three models.** Only one machine
  (16 GB) has ever been measured, and only a footprint measurement exists
  (CLAUDE.md: "~2.5 GiB footprint fresh, ~3.9–4.2 GiB warmed"), not a
  lower-bound stress test — so a fabricated minimum was not written. No
  RAM-based compatibility gate exists yet as a result.
- **`prompt_template_sha256` is an empty string for Qwen.** Real chat
  template fragments exist in `src/qwen36b.c` (`<|im_start|>`/`<|im_end|>`
  segments), but hashing an ad hoc concatenation now would fabricate a
  "verified" fingerprint without the actual T0.5/T4.4 parity-proof
  machinery behind it. Left unset on purpose;
  `direct_token_ingestion_candidate: false` reflects that honestly.
- T1.0 (model-free runtime package: `dist/install.sh`,
  `tools/package_hf.py` wiring for `models.json` as a staged release asset)
  was explicitly not started here — it depends on T2.1 per its own spec
  entry and is naturally the next task, not folded into this one.

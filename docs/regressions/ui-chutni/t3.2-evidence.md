## 1. Attachment storage (§5.8)

`~/.samosa/attachments/<id[0:2]>/<id><ext>` (blob) plus `<id>.json`
(metadata), where `<id>` is the SHA-256 of the bytes. The layout, the
per-shard `flock`, the temp-file → `fsync` → `rename` → directory-`fsync`
publication, and the `0700`/`0600` modes deliberately mirror
[src/read_cache.h](../../../src/read_cache.h) rather than inventing a second
convention — same local trust boundary, same crash-safety requirement, and
the same content-addressed publish race to guard against.

**Capabilities come from sniffing the bytes, never from the client's declared
type.** `X-Samosa-Media-Type` is accepted but not trusted; PNG/JPEG/WEBP/GIF
and `%PDF-` magic numbers decide whether an attachment is image-capable or
document-capable. A caller cannot get a `.pdf` treated as an image (or vice
versa) by lying in a header.

`attachment_ids` on a chat turn is resolved server-side: images become
`image_url` data URIs, PDFs are read through the existing
`doc_read_handler()` OCR/text-layer cascade and spliced in as a delimited,
explicitly-untrusted evidence block. The browser never builds either.

Verified modes on a live gateway:

```
drwx------  ~/attachments
drwx------  ~/attachments/ca
-rw-------  ~/attachments/ca/.lock
-rw-------  ~/attachments/ca/ca567167...609fa3.png
-rw-------  ~/attachments/ca/ca567167...609fa3.json
```

### Garbage collection

Unreferenced attachments are reclaimed after a 24-hour grace period, swept
opportunistically on upload. An attachment that has been sent in a turn is
marked `referenced_at` and is never reclaimed, and `DELETE` on it returns
`409` — it belongs to a message now.

## 2. Defect found: gateway crash in the PDF reader (pre-existing, fixed)

The document half of the new test crashed the whole gateway process
(`Abort trap: 6`). ASan named it exactly:

```
==6010==ERROR: AddressSanitizer: heap-use-after-free on address 0x6060000044f0
READ of size 4 at 0x6060000044f0 thread T2
    #0 json_free json.h:155
    #1 doc_read_handler samosa_gateway.c:2510
freed by thread T2 here:
    #1 doc_read_handler samosa_gateway.c:2478
```

**Root cause.** In `doc_read_handler()`'s PDF branch, the OCR-failure path
freed `ext_json` / `arena_ext` / `ext_raw` and then `break`-ed — but that
`break` leaves the *inner page* loop, not the outer batch loop, so the
unconditional cleanup after the loop freed the same three pointers a second
time.

**Blast radius (pre-existing, not introduced by T3.2).** `doc.read` is the
instructed reader for the Jobs find path, so **any** PDF page that triggered
OCR escalation and failed would abort the gateway — taking Chat, Jobs, and
the model backend supervision down with it. It was reachable before this
task; nothing had exercised that path.

**Fix.** The failure path now frees only what that iteration owns
(`ocr_raw`); the single cleanup after the loop remains the sole owner of the
shared allocations.

## 3. Defect found: a readable PDF was discarded when OCR was unavailable

With the crash fixed, `hello.pdf` still failed to extract. `needs_image` is a
*sparseness* heuristic (`toks < 20`), so a short-but-perfectly-readable page
escalates to OCR; on this machine OCR is genuinely unavailable
(`~/.samosa/models/ocr-pack-v1` is not installed), and the whole document
read then failed — **discarding text-layer content already in hand.**

**Fix.** When OCR escalation fails but the page has real text-layer text,
that text is emitted, labeled `source: "text_layer_ocr_unavailable"` so a
caller can tell it apart from both a clean text-layer read and OCR output
that never happened. A page with *no* text layer still fails honestly — there
is genuinely nothing to fall back on. The inline text-layer emitter was
extracted into `emit_text_layer_page()` so both paths produce byte-identical
page shapes.

`source` is a display label only (`ji_doc_read_source()` reports it to the
Jobs SSE stream and nothing branches on it), so the new value is additive.

## 4. Capability gating — what is honestly unavailable

Per §5.8, "the UI must not display a working action for a route absent from
the packaged gateway." Grepped across `src/` and full git history:

| Menu item | Backing route | State |
|---|---|---|
| Image | `POST /v1/attachments` + vision-capable ready model | **live** |
| Document | `POST /v1/attachments` + `samosa-extract`/`samosa-ocr` | **live** |
| Web page | `/v1/web/*` | **absent — disabled** |
| Directory | Chutni directory-context API | **absent — disabled** |

Neither `/v1/web/*`, nor `/v1/chutni/*`, nor `directory_context` exists
anywhere in the C source. Both items render disabled with the reason visible
on screen *and* in their `aria-label`, so the constraint reads the same to a
screen reader as it looks. They are not wired to click handlers at all — a
handler that silently did nothing would be worse than a disabled control.

`/healthz` gained `supports_documents`, reported from the actual presence and
executability of `samosa-extract` and `samosa-ocr` rather than from an
assumption that this build shipped them.

The Settings "Internet source" card (which called the three non-existent
`/v1/web/*` routes) is removed, along with its now-dead CSS and JS. This
closes the frontend half of the open "Internet-search feature does not exist"
defect in [CLAUDE.md](../../../CLAUDE.md); the docs half is still an owner
decision.

## 5. Performance: the 1,000-message acceptance gate

`renderMessages()` now materializes only the most recent 60 turns and reveals
older ones on demand, so render work is O(window), not O(conversation).

```
  1,000 messages: 61 nodes, 0.24ms (fixture DOM, no layout/paint)
     40 messages: 40 nodes, 0.15ms
```

**Scope of this measurement — read before quoting it.** This runs in Node
against a hand-rolled DOM fixture with no layout, style, or paint. The
absolute milliseconds are **not** a browser frame budget and must not be
reported as one. What it proves is the algorithmic property: node count is
bounded by the window and render time does not grow with conversation length.

The test's discriminating power was verified rather than assumed — forcing
`renderLimit` high (simulating the pre-windowing behavior) fails it:

```
AssertionError: a 1,000-message conversation must not materialize
every turn (rendered 1000 nodes)
```

## 6. Tests

New:

- **`tests/test_attachments.sh`** — 12 checks against a *real* compiled
  gateway: auth (401 without a token), sniffed capabilities, content-address
  stability on re-upload, `415` on an unsupported type, exact-byte `GET`
  round trip, `400`/`404` on malformed/unknown IDs, real `attachment_ids`
  resolution into an `image_url` data URI, `409` on deleting a referenced
  attachment, clean delete of an unreferenced one, and — when a real
  extractor is present — real PDF text reaching the outgoing request. Wired
  into `make compiled-gateway-test`.
- **`tests/test_composer_ui.mjs`** — DOM-fixture coverage of capability
  gating, upload headers (including a non-ASCII filename), failed-upload
  chips, the attachment cap, chip removal releasing the server blob,
  filenames rendered as text not markup, menu open/close/Escape, Tab wrapping
  that skips disabled items, and picker routing.
- **`tests/test_composer_perf.mjs`** — the 1,000-message gate above, plus
  empty-state escaping.

Both `.mjs` tests are wired into `make test-ui-setup`.

Full suites run on this machine:

`tests/test_attachments.sh` also passes under
`-fsanitize=address,undefined` — the build that caught defect #2.

### A test-infrastructure bug this surfaced

The new test's first port choice (`18997`, backend `18998`) collided with
`test_settings_compact_proxy.sh`'s *public* port. Combined with the crash
above leaving an orphaned fake backend bound to `18998`, that orphan answered
the other test's requests and made an unauthenticated route appear to return
`200` instead of `401` — a false pass-shaped failure in an unrelated test.
Moved to `19020`, and its cleanup now explicitly shuts the backend child down
so a failing run cannot leave a listener behind.

## What was NOT verified

Per the project's non-negotiables, stated plainly:

- **No real-browser click-through.** Everything frontend here is covered by
  DOM fixtures in Node. Screenshot capture is not possible in this
  environment. Rendering, focus behavior, and the menu's appearance in
  Safari/Chrome/Firefox are **not run**.
- **No real 24 GB Qwen model run.** All gateway tests use
  `tests/fake_openai_backend.c`. An image attachment reaching the real vision
  tower, and a real model reading a real attached PDF, are **not run**.
- **OCR-backed document attachment is not exercised** on this machine — no
  OCR pack is installed, so the document path was verified through the PDF
  *text layer* only. A scanned, image-only PDF still returns
  `attachment_extraction_failed` here, correctly and by design.
- **`directory_context` and web attachments** are disabled, not implemented.
- The GC grace period expiring is **not** time-travel tested; only the
  referenced/unreferenced branch is covered.

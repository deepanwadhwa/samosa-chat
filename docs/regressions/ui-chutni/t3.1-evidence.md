Branch: `ui-chutni`. Date: 2026-07-27. Machine: the reference machine (16 GB

`uname -a`: `Darwin MacBook-Air.local 25.5.0 ... RELEASE_ARM64_T8122 arm64`).

## Scope note

T2.1–T2.3 and T1.0 were already done, so T3.1 was the sole remaining blocker
for T2.4 (per the program tracker). This task is a frontend-only change to
`assets/app.html` — no backend/`src/*.c` files were touched.

Two scope boundaries were drawn deliberately, not by omission:

1. **The composer `+` menu (Image/Web page/Document) and moving the web-search
   card out of Settings are T3.2's work** ("Rebuild Chat and the composer"),
   not T3.1's. T3.1's own Work list stops at "Add Chat/Chutni/Jobs navigation,
   conversation region, bottom model status, and Troubleshooting surface" —
   it does not mention the `+` menu. Left untouched.
2. **The Jobs activity-log's per-event dot glyphs** (`✓ ✗ ● · ▦ ◇ › ⟳`,
   `renderJobEvent` in the script) were **not** folded into the new SVG icon
   family. `docs/UI_DESIGN.md`'s glyph-soup critique (sec1, tell #6)
   enumerates a specific, closed list of tells — `＋ ☰ ↑ ■ ✕ ×` — and T3.1's
   Work item is "one inline SVG icon family" replacing *that* list. The Jobs
   dot convention is a separate, already-shipped, already-tested mechanism
   (`tests/test_jobs_ui.mjs` asserts against it indirectly via `.title`
   text) with its own established meaning per dot; rewriting it was out of
   scope for a design-system-tokens task and risked the exact regression
   T2.3's evidence doc warned about (an unrelated integration test catching
   what an isolated new test cannot).

## Spec tension flagged, not resolved by guessing

T3.1's acceptance list requires "checked-in visual acceptance captures for
Name, Welcome, Model, Chat, and Chutni in light/dark and desktop/narrow
layouts." Name/Welcome/Model do not exist yet — T2.4 ("Ship Name → Welcome →
Model → Chat") is the task whose own Work list builds those four setup views,
and T2.4 explicitly *depends on* T3.1. Building placeholder onboarding screens
now would be scope creep into T2.4's stated ownership for no acceptance
benefit, since captures are blocked entirely in this environment regardless
(next section). Chat and Jobs exist and got the full token/subtraction pass;
Chutni got an honest placeholder pane (below). Revisit Name/Welcome/Model
captures when T2.4 lands and a real capture mechanism exists.

## Visual acceptance captures: blocked, not produced

This program's own memory record states there is no browser-automation tool
in this environment (no chromium/Chrome, no Playwright/Puppeteer). Before
assuming that also rules out a *static screenshot*, this was tested directly
rather than assumed:

```
$ screencapture -x /path/to/scratchpad/test-capture.png
could not create image from display
```

No file was produced. This CLI agent shell has no screen-recording/display
access, so `screencapture` (and by extension any Safari-driven capture via
`osascript`) cannot render or photograph the page here. **No screenshots were
produced or committed.** This is disclosed as an open gap rather than skipped
silently or faked — matching CLAUDE.md's evidence-not-assertion rule. The CSS/
markup changes below were verified by: (a) the existing automated JS/DOM and
gateway test suites, (b) a Python HTML tag-balance check, and (c) `node
--check` on the extracted script — not by eyeballing a rendered page. This
is real coverage of *plumbing correctness* (tags balanced, JS parses, DOM
fixtures still pass); it is not evidence of how the redesign actually looks
in a browser, which requires a human running it in one.

## What landed in `assets/app.html`

**Tokens (docs/UI_DESIGN.md sec2.2).** Replaced `--paper-2`/`--panel`/
`--brand`/`--brand-dark`/`--brand-soft`/`--muted`/`--user`/`--user-ink`/
`--assistant`/`--radius`/`--shadow` with the spec's named roles: `--surface`,
`--inset`, `--line`/`--line-strong`, `--ink`/`--ink-2`/`--ink-3`, `--accent`/
`--accent-ink`/`--accent-soft`, `--ok`/`--warn`/`--danger`, one
`--shadow-overlay`, a three-value radius scale (`--r-sm`/`--r-md`/`--r-lg`),
and `--font-ui`/`--font-mono`. Confirmed zero remaining references to any old
token name (`grep` for each, clean). Dark-mode values for roles the spec
didn't give literal hex for (`--inset`, `--ink-3`, `--ok`/`--warn` dark
variants) were derived from the previously-shipped dark palette rather than
invented from scratch, to preserve already-tuned contrast.

**Subtraction pass (docs/UI_DESIGN.md sec1 tells).** Removed: the two radial
background washes on `<body>`; the gradient + colored-glow primary button
(`.new-chat` is now flat `--accent`); `box-shadow` from the composer, message
bubbles, chat-item.active, prompt-chip, icon-button, jump-latest, and
image-preview (kept at exactly the one allowed level — `--shadow-overlay` —
on true overlays: Settings sheet, chooser dialog, mismatch dialog, migration
banner); `translateY(-1px)` hover-lift everywhere (`.new-chat`, `.send`,
`.stop`, `.prompt-chip` now tint/darken on hover, `scale(.985)` on press);
`backdrop-filter` blur from the sidebar (now flat `--paper` + hairline, per
sec2.4's explicit "no blur" rule) and the composer/image-preview (kept only
on the topbar and true overlays, the two places sec2.4 allows it); radius
chaos (22/18/15/14/13/12/11/10px) collapsed to the three-value scale; 10px
telemetry/composer-hint text raised to 12px (nothing below 11px, per sec2.3);
`tabular-nums` added to telemetry `<strong>` values and a global `.tabular`
utility; weight scatter (650/680/700/800) normalized to 400/500–600/700
(kept 700 only on the brand wordmark and message-avatar initial, both
one-off single-glyph/label treatments, not body text). Added
`@media (prefers-reduced-motion: reduce)` (zeroes animation/transition
duration and forces `scroll-behavior: auto`) and a global `:focus-visible`
ring (`0 0 0 3px var(--accent-soft)`) since none existed before.

**Icon family (docs/UI_DESIGN.md sec2.5).** Added 11 new inline SVG symbols
to the existing hidden sprite (which previously held only `icon-folder`):
`icon-plus`, `icon-x`, `icon-menu`, `icon-arrow-up`, `icon-arrow-down`,
`icon-arrow-left`, `icon-stop`, `icon-gear`, `icon-chat`, `icon-chutni`,
`icon-jobs` — 16/20px grid, `currentColor`, mostly 1.4–1.7px round strokes
(icon-stop is a filled square per its own component convention). Replaced
every enumerated glyph tell: `＋` (new-chat, attach button) → `icon-plus`;
`☰` (mobile sidebar toggle) → `icon-menu`; `↑` (send) → `icon-arrow-up`;
`■` (stop) → `icon-stop`; `✕`/`×` (remove-image, chat-delete) → `icon-x`;
`&larr;` (chooser "Up") → `icon-arrow-left`; `↓ Latest` → `icon-arrow-down` +
text. Settings gained a gear icon (previously text-only), matching the icon
inventory sec2.5 explicitly lists ("gear").

**Information architecture (docs/UI_DESIGN.md sec4.4, TASKS_UI_CHUTNI.md
T3.1 Work list).** The topbar's Chat/Jobs pill-switcher (`.view-tabs`) is
gone; navigation moved into the sidebar as `<nav class="nav">` with three
items — Chat, Chutni, Jobs — below the brand mark and above "New
conversation," so conversation creation/history sit beneath the nav per the
spec's literal ordering. `showView(name)` was generalized from a two-way
chat/jobs toggle to a three-way chat/chutni/jobs switch (`navEls` replaces
the old `jobEls.tabChat`/`tabJobs` refs). **Chutni has no scope views yet**
(that's T3.3, Phase 4 hasn't shipped) — its pane is an honest placeholder
("Chutni isn't built yet... Nothing is scanned until you explicitly add a
scope here"), not a fake affordance, consistent with the project's
honest-state culture. Sidebar footer now shows active model + a status dot
(`sidebarStatusDot`/`sidebarStatusText`, mirrored from the same `health()`
call sites that already drive the topbar dot/text — 4 call sites, all
updated) per sec4.4's "active model and local-runtime status appear at the
bottom [of the sidebar]." The existing topbar conversation-status line and
the existing bottom telemetry bar (Mode/Speed/Memory/Context/Closure) were
kept as-is functionally (only retokenized) rather than deduplicated — they
answer three different questions (this conversation's live state; which
model is active regardless of view; numeric generation telemetry) and
collapsing them wasn't asked for by the Work list.

**Troubleshooting surface (docs/UI_DESIGN.md sec4.4: "the primary header does
not contain a destructive Kill action").** The `Kill` button is no longer in
`.top-actions`. It now lives in a labeled `.troubleshoot-card` at the bottom
of the Settings sheet ("Troubleshooting" label, one explanatory sentence,
the same `confirm()`-gated `killLocal()` behavior, same `id="killButton"` so
no JS wiring changed beyond its DOM location).

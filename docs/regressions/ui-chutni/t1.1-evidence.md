Spec: [docs/TASKS_UI_CHUTNI.md](../../TASKS_UI_CHUTNI.md) T1.1 (Phase 1).
Branch: `ui-chutni`. Date: 2026-07-26. Machine: the reference machine (16 GB
Apple Silicon MacBook Air, macOS 26.5.1, Darwin 25.5.0 arm64).

## Scope note

T1.1's acceptance list includes "a clean Samosa data directory opens the
Name screen" — that screen doesn't exist yet (T1.2 profile/setup state,
T2.4 the actual Name→Welcome→Model→Chat views). This task is scoped to
what it can actually own today: **the control plane binds and stays alive,
and every route that exists today behaves honestly with zero models
installed.** T1.2/T2.4 build the screens this unblocks.

## What landed (`src/samosa_gateway.c`)

1. **`main()` no longer exits before binding the port.** Previously: `if
   (!backend_start(&gateway)) { fprintf(stderr, "...not installed\n");
   return 2; }` — this ran *before* `samosa_http_server_init()`, so a clean
   install with no model never got a listener, never served `/healthz`, root
   HTML, or anything else. Now: a failed `backend_start()` logs a clear
   stderr line and falls through to bind the port and run the server
   regardless. No new state needed for this — `backend_start()`'s own
   early-return-on-unavailable path already leaves `backend_pid` at 0 and
   `upstream_fd` at -1, which every existing consumer (`/healthz`,
   `backend_probe`, `proxy_request`) already interprets correctly as "not
   ready."
2. **`/healthz` gained two additive fields**: `"installed"` (is a model
   actually installed for the currently selected backend name — distinct
   from "ready", which also requires the process to be up and answering)
   and `"backend_state"` (`none`/`loading`/`ready`/`generating`/`failed`,
   the spec's exact enum). All existing fields (`gateway`, `compiled`,
   `backend`, `label`, `model`, `supports_images`, `ready`, `loading`,
   `generating`, `pid`) are unchanged — nothing renamed, nothing removed, so
   every existing test asserting on `/healthz`'s shape
   (`tests/test_compiled_gateway.sh`) needed no changes and stayed green.
3. **`/v1/chat/completions` (and `/v1/models`, via the same `proxy_request`)
   now returns `409 model_required`** with the shared error envelope when
   nothing is installed for the selected backend at all — checked *before*
   the network probe, since "no model" is a configuration fact, not a
   timing question. The pre-existing `503 backend_loading` (installed but
   the process isn't answering yet) and `503 backend_unavailable`
   (connection dropped) responses are unchanged for the cases they already
   correctly covered — this task only added the missing "nothing installed
   at all" case, matching T1.0's explicit acceptance
   ("Chat returns `409 model_required`").

Manually verified end-to-end with a clean, empty `$SAMOSA_HOME` (no model
fixtures anywhere):


## Test superseded, per its own stated intent

`tests/test_baseline_zero_model_startup.sh` (added in T0.1, explicitly
documented as "expected to be replaced once T1.1 lands — its assertions
describe the defect, not the target") is deleted. Replaced by
`tests/test_zero_model_startup.sh`, which asserts the new target behavior:
the process stays alive, `/healthz` reports `ready:false`/
`installed:false`/`backend_state:"none"`, root HTML still renders 200, and
Chat returns `409 model_required` rather than a dropped connection or a
process exit. Wired into `make test-ui-setup` in place of the retired test.

## Acceptance criteria

- **"A clean Samosa data directory opens the Name screen."** Partial: the
  Name screen itself is T1.2/T2.4. What's true today: a clean data
  directory no longer prevents the control plane from starting, and root
  HTML renders — the actual screen routing depends on T1.2's setup-state
  machine.
- **"`/healthz` clearly distinguishes a healthy control plane from model
  readiness."** Done — `backend_state:"none"` plus `installed:false` is
  unambiguous, and the control plane (the HTTP listener itself, `gateway`/
  `compiled` fields) is reachable independent of any of that.
- **"No compiler, model weights, or running inference backend is required
  to render setup."** Verified for what "setup" means today (root HTML) —
  confirmed rendering with zero model fixtures present.
- **"A clean runtime install completes without downloading Qwen or any
  other model."** Not this task's code — T1.0 (packaging/installer).
- **"A runtime-only upgrade does not stage, copy, or redownload existing
  model bytes."** Not this task's code — T1.0.
- **"Existing installed backends continue to be discovered."** Unchanged:
  `backend_available()` itself was not modified, only how its result is
  consumed. `make jobs-test`'s full `compiled-gateway-test` suite (which
  runs with a real Ornith fixture present and exercises the full Chat/Jobs
  path) stayed green, proving the installed-backend path is undisturbed.

## What T1.1 does not include

- The Name/Welcome/Model/Chat setup screens themselves (T1.2, T2.4).
- Model catalog, install, or selection APIs (T2.1–T2.3) — `backend_state`
  and `/v1/chat/completions`'s `409` are the control-plane side of "no
  model yet"; there is still no way to install one through this API layer.
- Aligning `model_required`'s error envelope with the frozen §5.0
  `{"error":{"code","message","retryable","details"}}` shape — this
  reused the gateway's existing, pre-existing
  `samosa_http_json_error()` envelope (`{"error":{"message","type","code"}}`),
  used consistently by every other route in this file. Migrating the whole
  file's error envelope is a larger, separate concern than this task; new
  v1-namespaced endpoints (T1.2 onward) should use the frozen §5.0 shape
  from the start.

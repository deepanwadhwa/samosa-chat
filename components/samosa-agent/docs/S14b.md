# S14b — correlated Inference children and live provider cancellation

C02/C07/C11 continuation owned by Agent and Inference at their published boundary.
A durable Agent submit run assigns bounded unique child IDs to count/generation
calls when Inference advertises operations/cancellation/operation_parents. Record
that association before spawning; Inference binds/echoes the parent ID in its
normalized request and durable public result/status. No parent ID grants authority
across a host-configured owner, or permission to cancel an entire parent group.

On Agent cancellation, send generic operation_cancel for that exact child through
a separate bounded configured command while the original worker is alive. Observe
its terminal public operation status before returning control to scoped helper
cleanup. Persist whether cancellation was observed or remains unconfirmed. Never
claim a long-lived provider stopped merely because its CLI helper was killed.
Keep unrelated operations alive. Terminal success remains authoritative on races.
Child IDs/request pins and control descriptors stay Agent/Inference-owned; no
consumer reads the other's private SQLite/cancel files. Maximum16 children per
Agent run, bounded control window, existing host histories/quotas still apply.

Include native controlled provider fixtures for binding, forged/wrong parent,
owner refusal, cancel/completion races, failed control and offline retry. Qualify
actual active model work and surviving subsequent output through Agent's public
cancel_run. Existing helper-only fake providers remain explicitly unqualified for
long-lived control. Source parent/deadline propagation, concurrent Agent admission,
public authenticated transport/App and whole-product resource gates remain open.
This is preparatory work; no legacy production path retires based on this subset.
Acceptance runners: make test-child-operations sanitize-child-operations (Agent),
make test-operations (Inference), then independent builds/sanitizers/releases and
explicit actual-provider runner. Record executed results in main checkpoint.

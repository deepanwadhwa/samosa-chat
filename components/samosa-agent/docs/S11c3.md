# S11c3 — checked effect receipt handoff

Preparatory C06/C10/C11 subset: after approved checked copy, move or inverse,
Agent asks configured Sources to observe receipt paths through locator_reconcile.
Physical effect receipts remain authoritative historical records; observations
have their own checkpoint freshness and cannot change an effect into a failure.

Owner: Agent actions.c and a native public-contract reconciliation helper. Agent
owns plans, receipts and persisted operation results. Sources owns observations.
No sibling includes, private database reads, new executor or Python dependency.
Unconfigured or failed Sources produces an explicit reconciliation qualification.
At most two batches of eight paths, 10-second configured command deadlines.
Expected versions and physical tuples come from committed own receipts. Returned
host/root scope must match the immutable plan root, and each result must match
the requested path/version/tuple. Completed retries return saved results before
filesystem or Sources access. A new execute operation can refresh observations.
Worker death during observation leaves durable physical receipts; recovery never
replays an already committed effect or silently publishes quarantined files.

Included: native helper, actions integration, focused native fake transport tests,
existing public action interaction extended to automatic handoff, contracts/docs.
Excluded: continuous watching, new source authority, scheduling, organization,
App, legacy retirement, logical source migration and broader milestone completion.

Acceptance: copy/move/inverse paths reconcile on matching root; wrong root/host,
version/tuple/response and unavailable Sources remain qualified independently of
successful effects. Exact retries make no new calls. Real independently built
Sources verifies the actual files. Existing action/recovery/sanitizer suites pass.
Focused commands added with runner. Complete after independent Mac/Linux checks;

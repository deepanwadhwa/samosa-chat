# S09c — one candidate, inspect, verify, select file-finding pipeline

C02/C08/C09 subset. Agent owns bounded file-finding policy; Sources owns literal
index/retrieval and evidence. Public `find_files` accepts job_id/query/max_inspect
(1..3) and uses configured Sources transport only. No model/action executor needed
for explicit literal matching. Candidate previews never count as verified evidence.

Implement Agent-owned pipeline and shared literal-evidence validation, reusing the
question policy validator. Search <=10 candidates, inspect <=3 exact immutable
versions/ranges, verify source/version/evidence/coverage and literal match, then
select verified results in deterministic manifest order. Return inspected/uninspected
counts, retained coverage, nonexhaustive current filesystem status, citations and
literal evidence. No inferred absence/counts or effects. Semantic classifiers and
folder answer synthesis are follow-on policy assignments, not silently simulated.

Acceptance: standalone native controlled public Sources adapter tests for forged
preview/evidence, mismatched versions/ranges, partial indexes, inspection bounds,
UTF-8/escaping, dependency failure, no Inference calls. Real independently built
Sources/Agent interaction over generated folder, duplicate filenames, interrupted
index, pinned past evidence after source deletion. Exact lexical fixture quality
expected selections plus bounded latency, not semantic-model quality claims.

Commands once runner exists: make test sanitize release; make test-find-interaction
SOURCES_EXECUTABLE=/independently/built/samosa-sources. No Python tools or imports.
Preparatory until product finding/default switch and broader quality gates pass;
legacy retirement belongs to qualified assembled replacement.
